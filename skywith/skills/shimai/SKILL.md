# 시마이 — 세션 마무리 정리

"시마이"는 작업 종료 신호다. 이번 세션에서 한 일을 깔끔하게 닫는다.
어느 프로젝트에서든 동작하도록 있는 도구·문서만 골라 쓴다.

## 1. 무엇을 했는지 파악
- `git status --short` + `git diff --stat` — 이번에 바뀐 파일
- 대화 맥락으로 "이번 세션의 목표/결과"를 정리

## 2. 검증 (코드가 바뀐 경우만)
- 프로젝트 `CLAUDE.md`의 검증 명령을 실행 (없으면 `package.json`/`Makefile` 확인): 예) `typecheck` → `lint` → `build` → 테스트.
  (실제 스크립트명은 `package.json`/`Makefile` 등에서 확인. 없으면 건너뜀.)
- 실패하면 **있는 그대로 보고**하고, 마무리보다 수정을 먼저 제안.

## 3. 기록 갱신 제안 (강요 X)
- **메모리**: 이번에 정해진 방향·결정·제약 중 다음 세션에 필요한 게 있으면 메모리 파일 작성/갱신 제안 (`MEMORY.md` 인덱스 한 줄 포함).
- **문서/로드맵**: `CLAUDE.md`·`docs/*` 의 진행 현황·로드맵에 반영할 변화가 있으면 어디를 어떻게 고칠지 제시.

### CLAUDE.md 효율성 원칙 (갱신할 때 반드시 적용)
`CLAUDE.md` 는 **매 세션 컨텍스트에 통째로 로드**된다 → 길이가 곧 비용·노이즈다.
"한 일을 다 적는 로그"가 아니라 **다음 세션이 적은 토큰으로 빠르게 정렬되는 지도**로 유지한다.

- **추가가 아니라 교체.** 새 줄을 덧붙이지 말고 기존 줄을 현재 상태로 고쳐 쓴다. 끝난 작업·중복·낡은 결정·해결된 함정은 **지운다**(git이 기억한다).
- **자명한 건 넣지 않는다.** 코드·`package.json`·git log·파일 구조에서 바로 보이는 건 제외. **비자명하고 지속되는 것만** 남긴다 — 제약, 함정(왜 이렇게 했는지), 결정의 근거, 외부 ref/키.
- **형식은 표·불릿 우선, 산문 최소.** 한 항목 = 한 줄. 같은 말 두 번 쓰지 않기(중복은 한쪽으로 링크/통합).
- **구체적이되 짧게.** 파일경로·명령어·ref는 정확히, 설명은 압축. 예: "`place_order` RPC가 가격 확정·재고 행잠금" 한 줄 ↔ 문단 X.
- **진행 현황은 누적 나열을 피한다.** 완료 단계를 계속 쌓지 말고 "현재 단계 + 다음 할 일"로 압축(로드맵 추적이 목적인 표는 상태 컬럼만 갱신).
- **변경 제안 시 "추가 N줄 / 삭제 M줄"을 함께 제시**해 순증가를 견제한다. 늘리기만 하는 갱신은 의심한다.

## 4. 커밋 마무리
- 변경을 논리 단위로 묶어 **커밋 메시지 초안**을 제안 (이 저장소 커밋 스타일에 맞춰).
- **사용자가 명시적으로 요청할 때만** 실제 커밋/푸시. 기본은 초안 제시까지.
- 기본 브랜치(main/master)면 브랜치부터 권한다.
- **푸시를 제안하거나 실행하기 전에 레포 공개 여부를 확인한다:** `gh repo view <owner/repo> --json visibility` (원격은 `git remote get-url origin`). `gh`가 없거나 확인하지 못하면 **공개로 간주**한다.
  - **PUBLIC이면** WIP·미완성 작업·내부 문서(사업·설계)·배포 정보를 올리지 않는다. 변경을 보존하려는 것이면 푸시하지 말고 **로컬 브랜치나 patch 파일**로 남긴다. 올려야 하면 `git diff`에서 `.env` 값·키·사설 주소가 없는지 확인하고, 공개 레포라는 사실을 알린 뒤 사용자 승인을 받는다.
  - 다른 기기에서 이어갈 작업이면 푸시 여부(공개/비공개)와 미푸시 커밋·브랜치를 요약에 적는다.

## 5. 포트폴리오 반영 후보 알림
프로젝트의 기능·구조·스택·성능 지표에 **의미 있는 변화**가 있었으면, 끝에 한 줄로만 알린다: "포트폴리오 반영 후보: <무엇>. `portfolio` 스킬로 진행할까요?"
실제 README/프로필 수정은 이 스킬에서 하지 않는다 (`portfolio` 스킬이 담당).

## 출력 형식
```
✅ 이번 세션 한 일
- ...

🔎 검증 결과
- typecheck/lint/build/test: ...

📝 기록 갱신 제안
- 메모리: ...
- 문서/로드맵: ... (추가 N줄 / 삭제 M줄)

🌟 포트폴리오 반영 후보 (있을 때만)
- ...

💾 커밋 초안
<type>: <요약>
```

검증 통과 + 기록 정리 + 커밋 초안까지가 "시마이"의 끝. 커밋·푸시 실행 여부는 사용자에게 묻는다.
