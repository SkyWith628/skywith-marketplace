# LLM Agent / RAG 실무 규칙

LLM·프레임워크 API는 버전에 민감하다. 구현 전 **공식 문서(또는 Context7)로 현재 API를 확인**한다.
NLP 기초(토크나이저·임베딩·어텐션 등)와 용어 풀이는 `glossary.md` (study 모드에서만 읽는다).

## 1. 프롬프트
- system 프롬프트로 역할·제약을 고정하고, **구조화 출력**(JSON 스키마)으로 파싱 안정성을 확보한다.
- 지시는 구체적으로, 형식은 예시(few-shot)로, 금지 사항은 명시한다.
- 추론이 필요한 작업은 단계별 사고(CoT)를 유도하되, 최종 출력 형식은 분리한다.
- **프롬프트는 코드다.** `prompts/`에 두고 git으로 버전 관리하며, 변경 시 평가셋으로 회귀 검사한다.

## 2. 에이전트
- **툴 호출**: 함수 스펙(이름·설명·인자 스키마)을 주면 LLM이 호출 JSON을 반환하고, 코드가 실행해 결과를 되돌린다. 툴 설명이 곧 프롬프트이므로 명확하게 쓴다.
- 패턴 선택: 단일 목표·툴 몇 개 → **ReAct 루프** / 복잡한 다단계 → **Plan-and-Execute** / 분기·순환·상태 필요 → **LangGraph 상태 그래프** / 역할 분담 → 멀티 에이전트. 단순한 구조로 시작하고 필요할 때만 올린다.
- 메모리: 단기(대화 히스토리, 길면 요약·트리밍) / 장기(벡터DB). 컨텍스트 윈도우를 넘기지 않는다.
- ⚠️ **폭주 방지 필수**: `max_iterations`, 타임아웃, 툴 호출 횟수 상한, 호출당 토큰 상한.
- 툴 실행 결과와 인자는 **신뢰하지 않는다**: 인자 검증, 위험한 툴(삭제·결제·메일 발송)은 사람 승인 단계를 둔다.

## 3. RAG
**인덱싱**: 문서 → 청킹 → 임베딩 → 벡터DB.
**검색**: 질문 임베딩 → top-k 유사도 → (리랭킹) → 프롬프트 주입 → 생성.
- **청킹**: 의미 단위(문단·헤딩)로 자르고 오버랩을 둔다. 크기·오버랩은 평가셋으로 정한다 (추측으로 고정하지 않는다).
- **벡터DB**: 로컬·프로토타입 FAISS/Chroma, 운영 pgvector/Pinecone 등. 임베딩 모델을 바꾸면 **전체 재색인**이 필요하다.
- **하이브리드 검색**(BM25 + 벡터)은 고유명사·숫자 질의에 강하다. **리랭킹**(Cross-Encoder)은 정밀도가 문제일 때 추가한다.
- 답변에는 **출처(청크 메타데이터)**를 함께 반환한다. 근거가 없으면 "모른다"고 답하게 한다.
- 메타데이터(문서 ID·페이지·갱신일)를 인덱싱 시점에 저장한다. 나중에 붙이기 어렵다.

## 4. 평가
생성형은 정확도만으로 부족하다. **평가셋을 먼저 만들고** 변경 때마다 재측정한다.
- RAG(RAGAS 등): Faithfulness(근거 충실도) · Answer Relevancy · Context Precision/Recall. 검색과 생성을 **분리해서** 본다.
- LLM-as-a-Judge: 루브릭을 명시하고, 판정 자체도 검증한다 (편향 존재).
- 에이전트: 최종 답뿐 아니라 **경로**(어떤 툴을 왜 호출했나), 스텝 수, 비용, 지연을 본다.

## 5. 보안·안정성·비용
- **프롬프트 인젝션**: 사용자 입력과 검색 문서는 명령이 아니라 **데이터**로 취급한다. 신뢰 경계를 분리하고 출력을 검증한다.
- **PII/비밀정보**: 프롬프트·로그에 개인정보·API 키를 남기지 않는다. 키는 `.env`.
- **환각**: RAG 근거 강제 + 출처 표기 + Faithfulness 평가.
- **비용·지연**: 토큰 사용량 로깅, 동일 질의 캐싱, 스트리밍 응답, 모델 티어 분리(간단한 작업은 소형 모델).
- 외부 API 호출은 재시도(지수 백오프)와 타임아웃을 건다.

## 6. 디렉터리 구조
```
agent/
├── config/config.yaml        # 모델명·temperature·top_k·청크 크기
├── ingest/                   # 로딩·청킹·임베딩·적재
├── retrieval/                # 검색·리랭킹
├── agents/{tools,graph}.py   # 툴 정의·상태 그래프
├── prompts/                  # 버전 관리 대상
├── eval/                     # 평가셋·RAGAS·회귀 테스트
└── api/ · .env · requirements.txt   # API·컨테이너 구조는 deploy 스킬
```
