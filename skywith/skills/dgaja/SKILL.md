# 드가자 — 세션 시작 브리핑

"드가자"는 작업 재개 신호다. 호출되면 아래를 순서대로 수행해 **짧고 실행 가능한** 브리핑을 만든다.
어느 프로젝트에서든 동작하도록, 있는 문서만 골라 읽는다 (없으면 건너뜀).

## 1. 컨텍스트 읽기 — 싼 것 먼저, 무거운 건 필요할 때만
**먼저 (항상, 거의 무료):** 이 셋은 묶어서 병렬로 읽는다.
- `git status --short` + `git log --oneline -5` — 떠 있는 변경 / 방금 한 일 (가장 싸고 신선한 신호)
- `MEMORY.md` 인덱스 — 본문 말고 한 줄 요약만 훑기
- 프로젝트 `CLAUDE.md` / `README.md` — 작업 가이드·컨벤션·로드맵, **`mode:` 값(study|work)**

**그다음 (조건부, 토큰 큼):** 위에서 잡힌 "현재 작업 영역"이 실제로 필요로 할 때만 펼친다.
- `docs/` 설계/구조 문서 (`ARCHITECTURE.md`, `CURRENT-STRUCTURE.md` 등) — 다음 작업이 스키마·구조를 건드릴 때
- 개별 메모리 파일 본문 — 인덱스 줄이 관련 있다고 가리킬 때만

> git은 줄이지 않는다(가장 싸고 신선하다). 줄이는 대상은 무거운 문서다 — 브리핑에 필요 없는데 통째로 읽지 말 것.

## 2. 짧은 리뷰 (5줄 이내)
- 지금 어디까지 와 있나 (로드맵 단계 / 완료 여부)
- 작업 트리에 떠 있는 미커밋 변경이 무엇을 향하나
- 메모리에 적힌 현재 방향/제약 중 지금 유효한 것

문서를 그대로 옮기지 말고 **현재 상태로 요약**한다. 군더더기 없이.

## 3. 다음 작업 제안
- 로드맵·미커밋 변경·메모리 방향을 종합해 **다음에 할 일 1~3개**를 우선순위 순으로.
- 각 항목은 "무엇을 / 왜 / 첫 단계" 한 줄.
- 애매하면 추측하지 말고 선택지를 제시해 사용자가 고르게 한다.

## 출력 형식
```
📍 현재 상태
- ...

🔧 떠 있는 변경
- ...

➡️ 다음 작업 (추천순)
1. ...
2. ...
```

- `mode: study`면 "다음 작업" 항목에 **오늘 익힐 개념 1개**를 덧붙인다. `work`면 생략.

이 스킬은 **읽고 정렬만** 한다 — 코드 변경/빌드는 사용자가 작업을 고른 뒤에.
