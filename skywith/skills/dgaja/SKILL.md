# 드가자 — 세션 시작 브리핑

"드가자"는 작업 재개 신호다. 호출되면 아래를 순서대로 수행해 **짧고 실행 가능한** 브리핑을 만든다.
어느 프로젝트에서든 동작하도록, 있는 문서만 골라 읽는다 (없으면 건너뜀).

## 1. 컨텍스트 읽기 — 싼 것 먼저, 무거운 건 필요할 때만
**먼저 (항상, 거의 무료):** 아래는 묶어서 병렬로 읽는다.
- **인수인계** — `시마이`가 남긴 `<인수인계 폴더>/<프로젝트>.md`를 **가장 먼저** 읽는다(폴더는 환경변수 `HANDOFF_DIR`, 없으면 iCloud 루트의 `_handoff/` — 위치·프로젝트명 규칙은 `시마이` §4와 같다). 없으면 레포의 `인수인계.md`(옛 방식), 그다음 자동 메모리의 `handoff.md`. 같은 폴더에 `<이름> (1).md` 충돌본이 있으면 두 기기가 동시에 썼다는 뜻이니 알린다.
- `git status --short` + `git log --oneline -5` — 떠 있는 변경 / 방금 한 일 (가장 싸고 신선한 신호)
- `git fetch --quiet` 후 `git status -sb` — 다른 기기·세션에서 푸시해 **뒤처졌는지(behind)**, 내가 앞섰는지(ahead) 확인. 오프라인이면 건너뛴다.
- **인수인계 대조** (fetch 뒤에). 헤더 `갱신·기기·브랜치·origin·미푸시·미커밋`을 현재와 비교한다.
  - 브랜치가 다르면 알린다. 갱신이 7일 넘었으면 낡았을 수 있다고, 파일이 없거나 방금 다른 기기에서 쓴 흔적이 안 보이면 "iCloud 동기화 대기 중일 수 있음"이라고 표시한다.
  - `origin/<브랜치>`가 헤더의 origin보다 앞서 있으면(`git rev-list --count <헤더 origin>..origin/<브랜치>`) "그 사이 N커밋 — `git pull` 먼저"라고 첫 줄에 알린다.
  - 헤더 origin 해시가 fetch 뒤에도 이 기기에 없으면 "이전 기기에서 푸시가 안 됐을 수 있다"고 알린다. 헤더 `미푸시`가 0보다 크면 그 커밋은 이전 기기에만 있다고 알린다.
  - 헤더가 없는 수동 작성본이면 파일 수정 시각과 `git log`로 대신한다.
- `MEMORY.md` 인덱스 — 본문 말고 한 줄 요약만 훑기. 메모리는 **프로젝트 폴더 경로에 묶인다**: 폴더를 옮겼거나 다른 기기면 비어 있을 수 있으니, 그때는 아래 문서를 우선한다.
- 프로젝트 `CLAUDE.md` — 작업 가이드·컨벤션·로드맵, **`mode:` 값(study|work)**. `README.md`·`할일.md`·`TODO.md`는 인수인계가 없거나 인수인계가 가리킬 때만 읽는다.

**그다음 (조건부, 토큰 큼):** 위에서 잡힌 "현재 작업 영역"이 실제로 필요로 할 때만 펼친다.
- `docs/` 설계/구조 문서 (`ARCHITECTURE.md`, `CURRENT-STRUCTURE.md` 등) — 다음 작업이 스키마·구조를 건드릴 때
- 개별 메모리 파일 본문 — 인덱스 줄이 관련 있다고 가리킬 때만

> git은 줄이지 않는다(가장 싸고 신선하다). 줄이는 대상은 무거운 문서다 — 브리핑에 필요 없는데 통째로 읽지 말 것.

## 2. 짧은 리뷰 (5줄 이내)
- 지금 어디까지 와 있나 (로드맵 단계 / 완료 여부)
- 작업 트리에 떠 있는 미커밋 변경이 무엇을 향하나. 수가 유난히 크면 `git diff --ignore-space-at-eol --stat`로 **줄바꿈 소음**인지 구분한다(Windows에서 흔함).
- 메모리에 적힌 현재 방향/제약 중 지금 유효한 것
- 작업 폴더가 OneDrive·iCloud 같은 **동기화 폴더 안**이고 `.git`이 있으면 한 줄로 경고한다(코드는 `~/dev` 같은 클라우드 밖에 둔다).
- 뒤처졌다면(behind) 작업을 시작하기 전에 `git pull`이 필요하다고 첫 줄에 알린다.

문서를 그대로 옮기지 말고 **현재 상태로 요약**한다. 군더더기 없이.

## 3. 다음 작업 제안
- 인수인계의 **➡️ 다음 작업**을 1순위 후보로 삼되, 현재 git 상태·로드맵으로 **다시 검증**한다(이미 끝났거나 바뀐 항목은 뺀다). 인수인계의 **⚠️ 결정 대기**는 그대로 먼저 알린다.
- 로드맵·미커밋 변경·메모리 방향을 종합해 **다음에 할 일 1~3개**를 우선순위 순으로.
- 각 항목은 "무엇을 / 왜 / 첫 단계" 한 줄.
- 애매하면 추측하지 말고 선택지를 제시해 사용자가 고르게 한다.

## 출력 형식
```
🔁 마지막 시마이: <일시 · 기기> (origin 기준 그 뒤 N커밋 · 미푸시 M)     ← 인수인계가 있을 때만

📍 현재 상태
- ...

🔧 떠 있는 변경
- ...

➡️ 다음 작업 (추천순)
1. ...
2. ...
```

- `mode: study`면 "다음 작업" 항목에 **오늘 익힐 개념 1개**를 덧붙인다. `work`면 생략.

이 스킬은 **읽고 정렬만** 한다 — 코드 변경/빌드는 사용자가 작업을 고른 뒤에. 작업을 마칠 때는 `시마이`로 다음 시작점(인수인계)을 남긴다.
