# 블로그각 — 강의자료 → 근거 붙인 기술 블로그 생성

"블로그각"은 **학습한 것을 남에게 설명 가능한 글로 바꾸는** 신호다.
강의 슬라이드·실습 코드·논문 요약 등을 입력받아, 공식 문서와 논문을 근거로 인용한
**복습용** 블로그 글을 만든다.

원칙: **근거 없는 단정 금지, 지어내기 금지, 복붙 금지.**
모르면 "출처 확인 필요"로 남기고 사용자에게 되묻는다.

---

## 파이프라인 — 5단계

### 1. INGEST (입력 파싱)
올라온 자료의 형식에 맞춰 핵심을 추출한다.
- **PDF** → `pdf` 스킬로 텍스트/표 추출
- **PPTX** → `pptx` 스킬로 슬라이드 텍스트·노트 추출
- **코드 파일** → 직접 `Read`, 핵심 로직·주석 파악
- **이미지만 있는 슬라이드**(텍스트 추출 불가) → 지어내지 말고 "이 슬라이드는 이미지라 내용 파악 불가, 설명 보완 필요"로 표시

**산출물**: `핵심 개념 3~7개` + `자료에서 뽑은 코드/그림 근거`.
개념을 나열만 하지 말고 "이 자료가 진짜로 말하려는 것"이 뭔지 한 줄로 압축한다.

### 2. PLAN (범위 확정) — ⚠️ 사용자 확인 지점
아래를 정하고 **애매하면 추측하지 말고 물어본다.**
- **다룰 개념**: INGEST에서 뽑은 것 중 글 하나에 담을 3~5개로 압축 (욕심내지 않기)
- **타깃 독자**: 6개월 뒤의 나 (다시 봐도 바로 이해되게)

압축한 범위를 1~2줄로 사용자에게 확인받고 3단계로 넘어간다.

### 3. RESEARCH (근거 보강) — 이 스킬의 핵심
핵심 개념마다 **1차 출처(primary source)**를 웹에서 찾는다.
근거의 신뢰도 우선순위:
```
1순위: 공식 문서 (PyTorch/TensorFlow/HuggingFace/LangChain/LlamaIndex/OpenCV/React/MDN 등 official docs)
2순위: 원 논문 (arXiv, 학회 페이지 — 예: Attention Is All You Need, ReAct, RAG, YOLO)
3순위: 표준 명세 / RFC / 라이브러리 릴리스 노트
4순위: 신뢰도 높은 2차 자료 (지양, 불가피할 때만)
```
- 도구: `WebSearch`로 후보 찾고 → `WebFetch`로 실제 내용 확인 (제목만 보고 인용하지 말 것)
- **각 핵심 주장 → 출처 URL 1개 이상**을 매핑한다.
- **공식 문서에 실린 "그 개념의 예제 코드"까지 함께 확보한다** — 이게 4단계 대조 분석의 기준선이 된다.
  공식 문서가 그 개념을 어떤 예제로 보여주는지 그대로 긁어온다. **예제가 없으면 "공식 예제 없음"으로 표시**(지어내지 않음).
- 검색해도 공식 출처를 못 찾은 개념은 **지어내지 말고 "출처 확인 필요" 플래그**를 달아 초안에 남긴다.

**산출물**: `{ 개념 → 출처 URL + 핵심 인용(짧게) + 공식 문서 예제 코드 }` 매핑 표. 이게 4단계 글의 뼈대가 된다.

### 4. DRAFT (초안 작성) — 바로 HTML로
`reference.md`를 읽고 `② 복습(review) 골격`(HTML)을 채운다. **markdown 중간단계 없이 처음부터 HTML로 쓴다.**
`tistory.html`의 클래스를 그대로 사용한다: 콜아웃 `div.box .note/.tip/.warn/.use`, 개념지도 `div.map`, 코드 구문강조 `span .cm/.st/.nu/.fn/.kw`, 표 스크롤 `div.ts`, 다음 전환 `p.next`. 아래 작성 규칙(말투·깊이·대조)은 형식과 무관하게 그대로 적용한다.

작성 규칙 (`study` 스킬의 용어 설명 형식을 글에도 적용. blog는 모드와 무관하게 단독으로 쓸 수 있다):
- **말투·문체 (사람이 쓴 것처럼)**:
  - **존댓말 기본** — `-습니다`체를 축으로, 가끔 `-인데요 / -더라고요 / -죠 / -거든요`를 섞어 실제 블로거처럼 말 걸듯 자연스럽게. 딱딱한 논문 투도, 지나친 반말도 아님.
  - **AI 티 지우기**: 문단마다 "즉, / 다시 말해, / 정리하면, / 요약하자면" 같은 정형 접속·마무리를 반복하지 않는다. 같은 문형·접속어를 연달아 쓰지 말 것.
  - **반복 부가설명 금지**: 이미 설명한 개념을 다른 절에서 또 풀어 쓰지 않는다. 앞서 다뤘으면 "앞에서 본 ○○"로 짧게 참조.
  - **정형 도입부 금지**: "복습용 노트 — 6개월 뒤의 나를 위해…" 같은 틀에 박힌 문구를 쓰지 않는다. 대신 **강의자료·예제 파일을 한두 문단으로 가볍게 리뷰**하며 시작한다 (무슨 자료였고, 뭘 다뤘고, 이 글에서 뭘 짚을지).
- **설명 깊이 = 최대**: "자명하다"고 건너뛰지 않는다. 핵심 개념마다 아래 6단계를 빠짐없이 다룬다. (단, 말투는 위 규칙대로 자연스럽게 — 6단계를 기계적 소제목으로 나열하지 말고 글 흐름에 녹인다.)
  ```
  ① 한 줄 정의 (용어 형식)  ② 비유·직관  ③ 정확한 정의(공식+출처)
  ④ 코드로 확인  ⑤ 왜 중요/언제 쓰나  ⑥ 흔한 실수·함정
  ```
  독자가 "그래서 이게 왜?"를 떠올릴 틈 없이 미리 답한다. 초보도 따라오게, 그러나 물타지 않게.
- **구조**:
  - **개념 지도**: 도입 직후 개념들의 관계를 다이어그램 한 장으로 (reference.md ① 5번). 이후 각 섹션은 지도의 한 칸을 채운다.
  - **연결 서사**: 각 섹션은 앞 섹션에서 이어받는 문장으로 시작하고 끝에 "→ 다음은 ○○" 전환을 둔다 (macro→micro).
  - **🔗 어디에 쓰나**: 개념마다 실무 활용처를 콜아웃 하나로 고정.
- **공식 예제 ↔ 실습 코드 대조 ★★ (이 스킬의 중심 축)**: 각 개념 섹션을 아래 3단으로 쓴다.
  1. **공식 문서는 이렇게 설명한다**: 그 개념을 공식 문서가 어떻게 정의·설명하는지(짧은 인용+출처) + **공식 문서에 실린 예제 코드**를 함께 보여준다.
  2. **강의 실습에서는 이렇게 썼다**: 사용자가 보낸 실습 코드를 나란히 놓는다(실행 결과는 주석으로).
  3. **대조 분석**: 둘을 놓고 `같은 점 / 다른 점 / 실습은 왜 이렇게 변형했나 / 실무에선 어느 쪽` 을 짚는다. 대조가 길면 표로(항목·공식 예제·실습 코드·차이·이유).
  - 엣지: **실습 코드가 없으면**(강의자료만) → 1번(공식 설명+예제)까지만. **공식 예제가 없으면** → 지어내지 말고 "공식 예제 없음(설명만)"으로 남긴다. 실습이 공식과 **거의 동일하면** "거의 동일, 차이는 X"로 짧게.
- **예제 배치 ★**: 예제를 글 끝에 몰아넣는 별도 "예제 모음" 섹션을 만들지 않는다. **각 예제를 관련 개념 섹션에 위 대조 형태로** 배치한다. 강의/실습에 나온 예제는 **하나도 빠짐없이 전수 수록**하고, 누락이 불가피하면 사용자에게 알린다.
- **용어 설명**: 전문 용어가 처음 등장할 때 반드시 `용어 (한국어 의미): 한 줄 설명 / 예시` 형식
- **코드 블록**: 실행 가능한 코드 + 결과 주석(필요 시 `[What]/[Why]/[How]`)
- **재구성 강제**: 강의자료·문서 **문장(산문)**을 그대로 복붙하지 않는다. 내 언어로 다시 쓴다 (저작권·표절 회피). 산문 인용은 짧게(15단어 미만), 출처 명시. 단 **공식 문서의 예제 "코드"는 대조 기준이므로 짧게 그대로 인용하되 출처를 붙인다**(코드 옆 산문 설명은 내 언어로).
- **출처 표기**: 본문 주장 옆 또는 글 하단 "참고 자료"에 링크. 어느 개념이 어느 출처인지 대응되게.
- **마무리**: 실전 패턴 "치트시트" + "핵심 N가지" 압축 요약으로 닫는다.
- **디자인/타이포그래피**: `reference.md` ① 스타일 **다크 전용** 기준 (Pretendard·17px·행간 1.8·720~760px·다크 팔레트). 콜아웃 💡 팁 / ⚠️ 주의 / 📌 핵심 / 🔗 어디에 쓰나.

### 5. VERIFY (품질 게이트) → 저장
아래 체크리스트를 통과해야 저장한다. 미달 항목은 고치거나, 못 고치면 글 안에 명시.
```
□ 모든 핵심 주장에 출처 링크가 있는가 (근거 없는 단정 0개)
□ 전문 용어 첫 등장 시 "용어(한국어): 설명 / 예시" 형식을 지켰는가
□ 코드가 있으면 실행 가능 + [What/Why/How] 설명이 붙었는가
□ 강의자료를 복붙하지 않고 내 언어로 재구성했는가
□ 존댓말·자연스러운 블로거 말투인가 (정형 접속·반복 부가설명·틀에 박힌 도입부·"(강의 전체)" 라벨 없음)
□ 도입부가 정형구 대신 자료를 가볍게 리뷰하며 시작하는가
□ 개념 지도가 있고, 섹션이 앞뒤로 연결되며, 개념마다 🔗 활용처가 있는가
□ 개념마다 공식 문서 설명(인용+출처)과 공식 문서 예제를 함께 제시했는가
□ 실습 코드가 있으면 공식 예제와 대조 분석(같/다/왜/실무)을 했는가
□ 공식 예제가 없으면 지어내지 않고 "공식 예제 없음"으로 표시했는가
□ 강의/실습 예제를 전수 대조해 누락 없이, 각자 관련 섹션에 배치했는가 (끝에 몰아넣지 않음)
□ 치트시트 + 핵심 N가지로 마무리했는가
□ 제목/날짜/태그를 상단 HTML 주석에 적어뒀는가 (티스토리 본문은 {{CONTENT}}만, 제목·태그는 티스토리 편집기에서 입력)
□ 설명 깊이 6단계(정의→직관→정확정의→코드→왜/언제→함정)를 개념마다 지켰는가
□ tistory.html 스켈레톤에 바로 채운 유효한 HTML인가 (div.box/map, span 구문강조, div.ts 사용 · 배경 transparent · 코드블록 단일 배경)
□ "출처 확인 필요" 플래그가 남아있으면 사용자에게 알렸는가
```

**저장 방식 (HTML 고정 — markdown 중간 산출물·.md 저장 없음)**: DRAFT에서 쓴 본문 HTML을 `tistory.html`의 `{{CONTENT}}` 자리에 주입해 완성본을 만든다 → 프로젝트 루트 `blog/` 폴더(없으면 생성)에 `.html`로 저장하고, 내장 브라우저(`file://` 경로)로 미리보기한다.
- **파일명**: `YYYY-MM-DD-<slug>.html` (예: `2026-08-05-yolo-loss-function.html`)
- **제목/날짜/태그**: 파일 최상단 HTML 주석에 남긴다(`<!-- title: … / date: … / tags: … -->`). 티스토리 본문엔 `{{CONTENT}}`만 붙이고, 제목·태그는 티스토리 편집기에서 입력.
- **스켈레톤**: `tistory.html` — 티스토리 HTML 모드 붙여넣기용 (`.rp` 스코프, 배경 `transparent`로 블로그 배경 그대로, 코드블록 단일 배경, 개념지도·구문강조·🔗use 콜아웃 포함). 디자인은 `reference.md` ① **다크 전용** 기준.

## 출력 형식 (작업 완료 시 사용자에게 보고)
```
📄 생성한 글
- 파일: blog/2026-08-05-....html
- 다룬 개념: A, B, C

🔗 인용한 출처
- 개념 A → <공식문서 URL>
- ...

⚠️ 확인 필요 (있으면)
- "..." 부분은 공식 출처를 못 찾음 — 보완 필요
```

이 스킬은 **자료 → HTML 초안 → 저장**까지 한다. 실제 블로그 플랫폼 게시는 하지 않는다(개선 방향).
